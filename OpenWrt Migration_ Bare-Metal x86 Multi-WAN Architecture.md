Phase 2 of the multi-WAN architecture represents the permanent, production-ready deployment. The goal is to migrate the OpenWrt routing stack from the Windows Hyper-V virtual machine onto a dedicated, low-power x86 server 1, 2\. This transition completely eliminates virtualization overhead, hypervisor-induced latency spikes, and the unpredictable nature of Windows USB RNDIS tethering drivers 1, 3, 4\.  
Here is a deep dive into the Phase 2 migration to a bare-metal mining motherboard:  
**1\. The Hardware Foundation**The target hardware is a repurposed cryptocurrency mining motherboard equipped with an Intel Celeron processor, 4GB of RAM, and a small SATA SSD 1, 5\.

* **Computational Superiority:** This x86 hardware provides massive CPU headroom compared to the constrained System-on-Chips (SoCs) found in standard consumer modems like the W9960 6, 7\.  
* **Bufferbloat Management:** This extra processing power is crucial because it allows OpenWrt to run Smart Queue Management (SQM) using the Cake Active Queue Management (AQM) algorithm, which aggressively eliminates bufferbloat on highly asymmetric DSL connections 6, 7\.

**2\. Physical Network Isolation**Mining motherboards are ideal for edge routing because they feature an abundance of PCIe x1 expansion slots 1, 7\. By installing a dedicated quad-port Gigabit Network Interface Card (NIC), you can physically isolate your WAN1 (VDSL), WAN2 (Cellular), and local LAN segments 8, 9\. This entirely eliminates the need to configure complex VLAN tagging on a single interface (a "router on a stick" topology) 8, 9\.  
**3\. Crucial NIC Selection: i350-T4 vs. i226-V**Network stability is paramount for a perimeter router, and not all NICs play nicely with the Linux kernel OpenWrt uses 8, 10\.

* **Intel i350-T4 (Highly Recommended):** This is the gold standard for this build. It is a proven, enterprise-grade quad-port card that uses the highly mature igb kernel driver 10, 11\. It natively supports hardware multi-queueing (VMDq) and interrupt offloading, which drastically reduces CPU strain 11, 12\. *(Note: Be cautious of counterfeits and prefer genuine server pulls 13).*  
* **Intel i226-V (Strongly Discouraged):** Although these newer cards offer 2.5GbE speeds, they suffer from severe stability regressions under OpenWrt 10, 14\. The igc or e1000e drivers frequently encounter fatal "Detected Hardware Unit Hang" errors or abrupt link losses, specifically due to conflicts between the Linux kernel's PCIe Active State Power Management (ASPM) and the silicon's TCP offloading engines 14-16. If you were forced to use one, you would have to manually disable hardware offloading (ethtool \-K eth1 tx off rx off...) and disable PCIe deep sleep states, which significantly increases CPU interrupt overhead 17-19.

**4\. The PCIe x1 Bandwidth "Bottleneck"**A common concern with mining boards is that their PCIe x1 slots physically limit expansion bandwidth. The recommended Intel i350-T4 is natively a PCIe 2.1 x4 card 11, 12\. When adapted to a PCIe 2.0 x1 slot, its maximum theoretical throughput is capped at the speed of a single PCIe lane—about 500 MB/s, or 4 Gbps 11, 12, 20.While a 4 Gbps cap would be a bottleneck if all four gigabit ports were saturated symmetrically, **this theoretical limit is entirely irrelevant for your dual-WAN scenario** 20, 21\. Combining a \~16 Mbps DSL connection with a mobile LTE connection will never come close to overwhelming a 4 Gbps PCIe link 20-22.  
**5\. Deployment and Provisioning Steps**

* **Hardware Assembly:** You will install the quad-port NIC using a powered PCIe x1-to-x16 riser cable. It is vital that this riser is supplied with auxiliary power directly from the PSU (via Molex or SATA) to prevent voltage dropouts on the PCIe bus during heavy network loads 4, 5\.  
* **Firmware Flashing:** You will boot the mining board from a live Linux USB drive and use the native Linux dd command to flash the ext4-combined-efi.img.gz OpenWrt image directly onto the internal SATA SSD 23, 24\.  
* **Interface Mapping:** Upon booting from the SSD, OpenWrt sequentially assigns hardware. Because the mining board has an onboard NIC, it almost certainly initializes as eth0 (which OpenWrt assigns to your LAN bridge) 25, 26\. The four external ports on the i350-T4 will then populate as eth1, eth2, eth3, and eth4, allowing you to cable your bridged W9960 to eth1 and your cellular modem to eth2 25-28.
